# 비전 → grab 모션 인터페이스

비전 쪽(`../vision/`)이 무엇을 주면 되는지, 그리고 로봇 쪽 제약이
무엇인지 정리한 문서입니다. **이 문서의 "확인 필요" 항목이 다 채워지기 전에는
실기에서 재생하지 마세요.**

## 1. 비전이 줘야 하는 것

물체 하나당 다음 네 값이면 충분합니다.

| 이름 | 단위 | 설명 |
|---|---|---|
| `u`, `v` | mm | 펙보드 평면 좌표 (지금 비전이 내는 그 좌표 그대로) |
| `angle_deg` | ° | 물체 긴 축이 보드 u축에 대해 돌아간 각도 |
| `width_mm` | mm | **집는 축 방향의 물체 폭** (아래 3절 참조) |

전달 방식은 아무거나 좋습니다. 가장 단순한 건 JSON 한 줄입니다.

```json
{"u": 12.5, "v": -8.0, "angle_deg": 31.4, "width_mm": 75.5}
```

로봇 쪽은 이걸 받아서 이렇게 씁니다.

```bash
./plan_grab.py plan --board 12.5,-8 --grip-angle 121.4 --object-width 75.5 \
                    --slot 11 --name GRAB_AUTO
```

`--grip-angle` 은 **물체 긴 축에 수직**입니다 (`angle_deg + 90`). 긴 축을 가로질러
집어야 물리기 때문입니다.

## 2. 좌표 정렬 — ★ 확인 필요

비전 좌표의 원점은 지금 "임의의 구멍"이고, 로봇 월드 원점(두 팔 J1 의 중점)과
정렬돼 있지 않습니다. 둘을 잇는 2D 강체변환을 **한 번 실측해야** 합니다.

측정 절차:

1. 펙보드 위 서로 떨어진 점 3개 이상을 고릅니다(구멍이 좋습니다).
2. 각 점의 비전 좌표 `(u, v)` 를 읽습니다.
3. 같은 점에 팔 끝을 대고 로봇 좌표 `(X, Y)` 를 읽습니다.
   `main/motion_builder/motion_builder.py` 의 **`현재각 → EE`** 버튼이 그 값을 줍니다.
4. 대응쌍을 넣어 변환을 풉니다.

```python
import frame
pairs = [((0,0), (-20.1, 35.4)), ((100,0), (78.2, 41.0)), ((0,80), (-26.3, 114.9))]
fr, residual = frame.solve_from_pairs(pairs)
print(fr, "최대 잔차", residual, "mm")
frame.save(fr)          # calibration.json 으로 저장
```

`calibration.json` 이 없거나 `calibrated: false` 면 `--board` 입력이 항등변환으로
처리되고 CLI 가 경고합니다. 잔차는 **2mm 이하**를 목표로 하세요.

## 3. 로봇 쪽 제약 — 설계에 반드시 반영해야 하는 것

### 그리퍼가 없습니다

이 로봇의 grab 은 **양팔이 물체를 양옆에서 좁혀 무는 대칭 핀치**입니다
(기존 슬롯 2 `grab` 모션을 디코드해서 확인). 손목도 없어서 EE 자체는 못 돌립니다.
대신 두 팔의 목표점을 회전시켜 **집는 축 방향**은 바꿀 수 있습니다(`--grip-angle`).

집는 순간 두 EE 간격은 기본 **60mm**(`close_half_gap` 30 × 2)입니다.
따라서 **집는 축 방향 물체 폭이 60mm 보다 커야** 물립니다.

- 물체 75.5 × 53.7mm 기준: 긴 축(75.5)을 가로질러 집으면 물림량 15.5mm — 잡힙니다.
- 짧은 축(53.7)을 가로질러 집으면 60mm 간격에 안 닿아 **그냥 빠집니다.**
- `--object-width` 를 주면 CLI 가 이걸 검사해서 경고합니다.

### 집을 수 있는 영역

두 팔이 동시에 닿아야 하므로 영역이 좁습니다. `./plan_grab.py reach` 로 확인하세요.
기본 파라미터(Z=120, 반간격 30) 기준 대략 **X ∈ [-70, +70], Y ∈ [-60, +160] mm** 입니다.

### ★ 가장 중요 — 실시간 루프가 불가능합니다

이 로봇은 **미리 SD 카드에 적재된 슬롯만 재생**할 수 있습니다.

- `PlayMotionSequence` 액션은 슬롯 ID(1~50)만 받습니다. 궤적 데이터를 못 보냅니다.
- 내부 서비스 `SubmitMotionRequest` 도 `uint8 motion_id` 뿐이고, 메시지 주석에
  **"이 서비스는 참가자 API 가 아니다"** 라고 명시돼 있습니다.
- RT 관절 스트리밍(`PhorceCommand`)은 죽어 있습니다. 메시지 주석:
  *"지금은 pcm ctrl frame 자체가 나가지 않는다 — `_FlushOutputs` 호출부가 삭제된
  상태가 **해커톤 의도 구성**이다(P-Vector 전용)."*

따라서 "비전이 본 위치로 즉시 팔을 보낸다"는 안 됩니다. 두 가지 방식 중에 골라야 합니다.

## 4. 두 가지 운용 방식

### 방식 A — 슬롯 그리드 (실시간 데모용)

작업 영역을 격자로 나눠 각 격자점의 grab 모션을 미리 만들어 슬롯에 깔아둡니다.
런타임에는 비전 좌표에서 **가장 가까운 슬롯을 골라 재생**만 합니다.

```bash
./plan_grab.py grid --slots 6-47 --spacing 8 --x-range -30 30 --y-range 10 70
./plan_grab.py nearest --board 12.5,-8      # → 재생할 슬롯 번호
phorce play <슬롯> --domain-id 21
```

빈 슬롯이 42개(6~47)뿐이라 덮을 수 있는 영역이 제한됩니다. 실측값:

| 작업 영역 | 자동 선택 간격 | 최대 위치 오차 |
|---|---|---|
| 60 × 60 mm | 11 mm | **7.1 mm** |
| 80 × 80 mm | 14 mm | 14.1 mm |
| 100 × 100 mm | 17 mm | 21.2 mm |
| 140 × 140 mm | 23 mm | 21.1 mm |

물체 75.5mm 를 60mm 간격으로 무는 여유가 15.5mm 이므로, **60×60mm 영역
(오차 7.1mm)까지가 현실적**입니다. 그보다 넓히면 물체를 놓치거나 밀어버립니다.

그리고 이 방식은 **집는 축 각도가 그리드 생성 시점에 고정**됩니다. 물체가 매번
다른 각도로 놓인다면 각도별 그리드가 필요한데 슬롯이 모자랍니다. 물체 방향을
일정하게 두는 운용이 필요합니다.

### 방식 B — 매번 재생성 (정밀, 느림)

비전이 준 위치로 정확한 모션을 만들어 SD 에 설치하고 PCM 을 재시작한 뒤 재생합니다.
위치·각도 오차가 없지만 한 사이클에 **SD 카드를 물리적으로 옮기고 PCM 을 재시작**해야
해서 수 분이 걸립니다. 시연용 루프로는 못 씁니다.

```bash
./plan_grab.py plan --board 12.5,-8 --grip-angle 121.4 --object-width 75.5 \
                    --slot 11 --name GRAB_AUTO
../../../main/motion_builder/install_to_sd.sh out/GRAB_AUTO <SD마운트경로>
# SD 를 PCM 에 꽂고 완전 재시작 → phorce play 11 --domain-id 21
```

## 5. 확인 필요 항목 정리

| # | 항목 | 왜 필요한가 |
|---|---|---|
| 1 | 비전↔로봇 좌표 변환 실측 (2절) | 안 하면 좌표가 통째로 어긋납니다 |
| 2 | 집는 높이 `grasp_z` 실측 | 기본 120mm 는 기존 grab 모션 값. 펙보드 높이+물체 높이로 다시 재야 합니다 |
| 3 | 물체를 무는 간격 `close_half_gap` | 기본 30(간격 60mm). 실제 물체 폭에 맞춰 조정 |
| 4 | 놓을 자리 `place_xy` | 기본 (0, 110) 은 기존 grab 모션 값. 실제 목표 위치로 바꿔야 함 |
| 5 | 방식 A / B 중 선택 | 실시간이면 A(영역 60×60mm 제한), 정밀이면 B(SD 왕복) |
| 6 | 물체 방향을 고정할 수 있는지 | 방식 A 는 집는 축이 고정입니다 |
| 7 | 관절 가동범위 | 이 플래너는 ±360° 만 검사합니다. 실제 기구 한계는 모릅니다 |
| 8 | 자기충돌 | 두 팔이 서로/구조물과 부딪히는지 검사하지 않습니다 |

7·8번은 **sim 재생만으로는 검증되지 않습니다.** 실기 투입 전에 사람이 눈으로
확인해야 합니다. 게다가 pcm 은 cancel 을 거부하므로 발사한 모션은 끝까지 갑니다.
